# Автоматизированный M&A-онбординг: ИНН → оценка → тизер → предложение владельцу

Система холодного M&A-аутрича. На вход — ИНН компании, контакт и сайт. На выходе владелец
бизнеса получает персональное сообщение с готовой презентацией-тизером, где посчитана
индикативная стоимость его компании и предложено обсудить продажу. Весь цикл — от ИНН до
отправленного оффера — занимает минуты и идёт без участия человека.

Раньше один такой тизер аналитик готовил примерно рабочий день: собрать данные из реестров,
посчитать оценку по методике, сверстать презентацию инвестиционного качества, найти контакт,
написать обращение. Теперь это пять минут на компанию, поэтому можно работать с потоком, а не
с единичными сделками. Конверсия из холодного обращения в due diligence — 7%.

> Заказчик не раскрывается по условиям NDA. Репозиторий описывает систему и её архитектуру.
  
## Как это работает

```
ИНН + контакт + сайт
        │
        ▼
1. ДАННЫЕ        spark_client (СПАРК-Интерфакс, премиум)   ─┐
                 data_fetcher (ГИР БО — финансы, бесплатно) ├─→ бандл по компании
                 OFData / Dadata (реквизиты, риски)        ─┘   (+ кэш 24ч)
        │
        ▼
2. ОЦЕНКА        Claude (opus 4.8) идёт по ДЕРЕВУ РЕШЕНИЙ методики:
                 метод выбирается под бизнес — EV/EBITDA для прибыльного,
                 капитализация дохода для недвижимости, NAV/ликвидация для
                 проблемного, EV/Sales для растущего. Нормализация прибыли,
                 отраслевые мультипликаторы, дисконты за размер и риски.
        │
        ▼
3. ТИЗЕР         chart_builder (графики Big3, точные цифры) → render_html
                 (HTML/CSS → Chromium → PDF). Фото обложки отбирает vision.
                 8 слайдов: позиционирование, executive summary, профиль,
                 рынок, финансы, катализаторы, football-field оценки, контакт.
        │
        ▼
4. РАССЫЛКА      outreach_agent пишет владельцу персональное предложение и
                 САМ ВЫБИРАЕТ канал: сначала Telegram, иначе e-mail
                 (telegram_sender / email_sender).
        │
        ▼
   тизер доставлен владельцу
```

Точка входа во весь цикл — `run_origination.py`. Отдельно работает `bot.py`: Telegram-бот,
которому можно прислать ИНН и получить тизер в ответ.

## Оценка по дереву решений

Стоимость считает не код, а Claude, проходя по формальному дереву из `valuation_methodology.md`.
Дерево само определяет метод по природе бизнеса:

- банкротство, ликвидация или отрицательный капитал — ликвидационная / чистые активы;
- недвижимость и гостиницы (ОКВЭД 68/55) — капитализация дохода по cap rate;
- финансовые компании — оценка по капиталу (P/B) и P/E;
- стабильно прибыльный операционный бизнес — мультипликаторы EV/EBITDA, для среднего и
  крупного дополнительно DCF;
- убыточный, но быстро растущий — по выручке (EV/Sales) с фазой роста;
- волатильная прибыль — нормализация по трём годам, вес мультипликатора выше DCF.

Дальше идут корректировки: чистый долг в мосте EV→Equity, скидка за размер для малого
бизнеса, серая выручка, риск-флаги (суды, ФССП, блокировки счетов, налоговые долги).
Оценка всегда диапазоном, а не точкой, и заведомо консервативная: публичная отчётность не
видит бренд, клиентскую базу и контракты, поэтому в тизере об этом сказано прямо.

Числа мультипликаторов и дисконтов вынесены в `valuation_params.yaml` и `valuation_benchmarks.yaml`
и откалиброваны бэктестом на реальных сделках (`backtest_report*.md`).

## Источники данных

| Блок | Источник | Стоимость |
|---|---|---|
| Финансы (РСБУ, ~5 лет) | ГИР БО (bo.nalog.gov.ru) | бесплатно |
| Реквизиты, риски, аффилированность | **СПАРК-Интерфакс API** (премиум) → OFData → Dadata | по подписке / free-tier |
| Макро (ставка ЦБ, ОФЗ) | ЦБ РФ | бесплатно |

СПАРК подключается через `spark_client.py` и включается, только если в `.env` заданы
`SPARK_API_URL/LOGIN/PASSWORD`. Когда СПАРК настроен, его авторитетные данные по реквизитам,
рискам и аффилированности подменяют бесплатные источники; финансы берутся из ГИР БО.
Без СПАРК-кредов система так же работает на бесплатных источниках — просто с чуть меньшей
достоверностью.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium        # Chromium для рендера PDF
cp .env.example .env                          # впиши ключи (см. ниже)
cp valuation_params.example.yaml valuation_params.yaml            # параметры оценки
cp valuation_benchmarks.example.yaml valuation_benchmarks.yaml    # отраслевые бенчмарки

# полный цикл: оценить и отправить владельцу
.venv/bin/python run_origination.py 7743195810 --tg @owner --site https://site.ru

# только тизер (PDF в output/<инн>/)
.venv/bin/python generate_teaser.py 7743195810 https://site.ru

# Telegram-бот: присылаешь ИНН — получаешь тизер
.venv/bin/python bot.py
```

Ключи — в `.env` (см. `.env.example`): СПАРК, LLM-эндпоинт (Polza AI, OpenAI-совместимый),
Telegram-токен и SMTP для почты. Любой источник без ключа просто пропускается.

## Структура

| Файл | Что делает |
|---|---|
| `run_origination.py` | полный цикл: ИНН+контакт → тизер → рассылка |
| `generate_teaser.py` | оркестратор тизера: данные → Claude → графики → PDF |
| `spark_client.py` | клиент СПАРК-Интерфакс API (премиум-данные) |
| `data_fetcher.py` | сбор данных из ГИР БО / OFData / Dadata по ИНН |
| `claude_client.py` | вызовы LLM (текст + vision) к Anthropic-совместимому API |
| `chart_builder.py` | графики уровня Big3 (matplotlib → PNG) |
| `render_html.py` | вёрстка тизера HTML/CSS → PDF через Chromium |
| `outreach_agent.py` | пишет владельцу и выбирает канал доставки |
| `telegram_sender.py` / `email_sender.py` | доставка тизера в Telegram / по почте |
| `bot.py` | Telegram-бот: ИНН на входе → PDF на выходе |
| `valuation_methodology.md` | дерево решений и формулы оценки |
| `valuation_params.example.yaml` / `valuation_benchmarks.example.yaml` | пример мультипликаторов/бенчмарков (продакшн-калибровка хранится приватно) |

Пример выхода — в `samples/` (тизер по ООО «Кармин-Авто», публичные данные).

## Требования

Python 3.11+, Chromium через Playwright. Для красивых графиков с символом ₽ нужен шрифт
PT Sans; на Linux ставится пакетом `fonts-paratype` (иначе подхватится DejaVu Sans — тоже
с кириллицей и ₽). Зависимости — в `requirements.txt`.
