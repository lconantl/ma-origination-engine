# Slide Playbook: что писать, какие графики, какие изображения — по слайдам
### Контракт агента-составителя контента → передаётся в рендер (Presenton / render_pptx.py)

> Этот документ — НЕ про дизайн (он в `presentation_design.md`), а про **наполнение**:
> для каждого слайда точно сказано, какой ТЕКСТ, какой ГРАФИК и какое ИЗОБРАЖЕНИЕ
> на нём должно быть. Агент (Claude) заполняет структуру ниже фактами/оценкой и
> отдаёт её слою оформления. Слой оформления (Presenton-шаблон или python-pptx)
> только верстает — он НЕ придумывает контент и НЕ выбирает картинки.
>
> Жёсткое правило: **ничего не выдумывать.** Все цифры — из data_fetcher / рынка /
> сравнимых. Все изображения — реальные, проверенные зрением. Где данных нет — поле
> пустое (слой оформления его не рисует).

---

## 0. Общие правила наполнения (применять ко всем слайдам)

- **Заголовок = action-title** (вывод-предложение с «так что», ≤2 строк). Не ярлык.
- **Один посыл на слайд.** Текста — минимум, цифры — в графиках/карточках.
- **Числа:** округлять, единицы, разряды пробелом. Перепроверять арифметику
  (напр. «×3» должно сходиться с графиком — иначе due-diligence ловит ложь).
- **Не противоречить данным.** Если последняя точка графика падает — заголовок не
  может говорить «растёт» без оговорки; помечать год-исключение прямо на графике.
- **Тон холодного оффера:** уверенный, фактический, без давления и без обещаний цены.
  Не «предоставьте отчётность — дадим больше» (звучит как намёк на серое), а
  «доступ к управленческой отчётности обычно уточняет диапазон».
- **Источник** в футере каждого слайда с данными.

## 1. СТРУКТУРА ВЫХОДА (агент заполняет это и отдаёт в рендер)

```yaml
deck:
  brand_color_primary: "#04244A"   # синий (по умолчанию McKinsey-navy)
  brand_color_accent:  "#00A9CE"   # голубой
  logo_path: <путь к ПРОВЕРЕННОМУ логотипу или null>

slides:
  - id: cover
  - id: exec_summary
  - id: company
  - id: market
  - id: financials
  - id: catalysts        # ДО оценки!
  - id: valuation
  - id: contact
```

Порядок зафиксирован пирамидой: summary → кто → рынок → результаты →
**драйверы апсайда → оценка** (оценка читается как следствие) → CTA.

## 2. СЛАЙД 1 — ОБЛОЖКА (cover)

| Что | Содержание | Правило |
|---|---|---|
| **Изображение** | **ЛОГОТИП компании** (обязательно, если найден чистый) | см. раздел 8 — поиск + ВИЗУАЛЬНАЯ проверка. Не нашли чистый → без картинки (чистая типографика) |
| **Текст 1** | название бизнеса (как в реестре) | напр. ООО «Кармин-Авто» |
| **Текст 2 (главный)** | позиционирование одной фразой | «Производитель … с потенциалом …» |
| **Текст 3** | «Инвестиционная возможность» | капсом, акцентом |
| **Текст 4** | дата (месяц год) | |
| **Цвета** | синий фон + голубой акцент | по brand_color |
| Графиков | нет | |

Поля для рендера:
```yaml
cover: {logo_path, company_name, positioning, subtitle: "Инвестиционная возможность", date}
```

---

## 3. СЛАЙД 2 — РЕЗЮМЕ (exec_summary)

| Что | Содержание |
|---|---|
| Action-title | весь тезис одним предложением (но НЕ перегружать: ≤2 идеи, остальное в подзаголовок) |
| Левая колонка | 1 абзац о бизнесе + 5–6 хайлайтов (буллеты-выводы) |
| Правая карточка | **бизнес-метрики** (НЕ «100% долей» — это перименр сделки, агрессивно для первого контакта): выручка, EBITDA, клиентская база, оценка EV |
| Графиков | нет (только карточка с цифрами) |
| Изображение | нет |

```yaml
exec_summary:
  action_title, one_liner, highlights: [..6..],
  key_figures: {revenue, ebitda, clients, ev_range}   # бизнес-метрики, не доля
```

## 4. СЛАЙД 3 — О КОМПАНИИ (company)

| Что | Содержание |
|---|---|
| Action-title | в чём устойчивость ниши/модели |
| Левый блок | профиль: основана, география, команда, бренды, модель (равный шаг строк, без дыр) |
| Правый блок | эксклюзивы + периметр сделки (связанные ИНН/ИП) |
| График/схема | опц.: простая схема бизнес-модели (каналы → клиенты). Фото — НЕТ |
| Изображение | нет (искл.: для недвижимости/завода — 1 фото актива, см. раздел 8) |

```yaml
company: {action_title, founded, location, team_size, brands[], business_model, exclusives[], deal_perimeter[]}
```

---

## 5. СЛАЙД 4 — РЫНОК (market)

| Что | Содержание |
|---|---|
| Action-title | почему рынок привлекателен (рост/импортозамещение) |
| **График** | объём рынка по годам (бары). Акцент — на ПИК, не на год спада. Год-исключение пометить («2025 — коррекция»). CAGR считать по фазе роста, не противоречить падению последней точки |
| Правый блок | драйверы (импортозамещение, уход иностранцев, локализация, экспорт) + риски мелким |
| Изображение | нет |

```yaml
market:
  action_title, tailwinds[], risks[], sources[]
  chart: {type: bars, years[], values[], unit, last_note: "2025 — коррекция"}
```

---

## 6. СЛАЙД 5 — ФИНАНСЫ (financials)

| Что | Содержание |
|---|---|
| Action-title | track record + честная интерпретация (просадку объяснить, арифметику проверить!) |
| **График 1** | выручка по годам (бары, акцент на пик, прямые метки) |
| **График 2** | EBIT (бары) + маржа EBIT (линия) — ЛИНИЯ ОБЯЗАНА иметь подпись/правую %-ось, иначе непонятно «что за линия». Год инвестиций пометить |
| Комментарий | «так что» (не пересказ цифр): драйвер роста, природа просадки, нормализованная EBITDA |
| Изображение | нет |

```yaml
financials:
  action_title, commentary
  charts: [revenue_trend, profit_margin]   # из chart_builder; маржа-линия подписана
```

## 7. СЛАЙД 6 — КАТАЛИЗАТОРЫ (catalysts) — ДО оценки

| Что | Содержание |
|---|---|
| Action-title | конкретика апсайда (не повторять третий раз «кратный рост» — дать новый факт, напр. «OEM-канал кратно расширяет адресуемый рынок») |
| 3–4 карточки | каждый катализатор: заголовок + 1–2 предложения. Карточки не гигантские (текст ≥ ½ высоты), заголовки в 2 строки зарезервированы для общего baseline |
| Графиков | нет (framework из карточек) |
| Изображение | нет (опц. иконка-маркер на карточке) |

```yaml
catalysts: {action_title, items: [{title, text}, ... 3-4]}
```

---

## 8. СЛАЙД 7 — ОЦЕНКА (valuation)

| Что | Содержание |
|---|---|
| Action-title | диапазон + честная рамка (по публичным данным консервативно; управленческие данные уточняют). НЕ «дадим больше за серую отчётность» |
| **График** | football-field: диапазоны по методам, подписи min/max СНАРУЖИ полос, единая ось X, пунктирная линия базы с явной подписью |
| Правый блок | «Что увеличит оценку» (нормальным кеглем, буллеты) + дисклеймер (петитом, но читаемо) |
| Метод | короткой сноской |
| Изображение | нет |

```yaml
valuation:
  action_title, method, justification, upside_drivers[], disclaimer
  chart: {type: football_field, methods: [{name, low, high}], base, unit}
```

---

## 9. СЛАЙД 8 — КОНТАКТ / NEXT STEPS (contact)

| Что | Содержание |
|---|---|
| Headline | «Готовы к диалогу» / «Следующий шаг» |
| **Rationale для собственника** (важно, часто забывают!) | что даёт сделка ВЛАДЕЛЬЦУ: ликвидность, партнёр для рывка, сохранение команды/роли |
| Идентификация отправителя | тип инвестора (стратег/фонд/консолидатор) + контакт. НЕ оставлять `[advisor]` пустым |
| Режим | NDA для дальнейшего диалога |
| Изображение | нет |

```yaml
contact: {headline, owner_rationale, cta, sender_identity, confidentiality}
```

## 10. УНИВЕРСАЛЬНЫЕ ПРАВИЛА ВЫБОРА ИЗОБРАЖЕНИЙ (image policy)

**Принцип:** изображение допускается, только если оно НЕСЁТ СМЫСЛ. Декоративные фото
(продукт, запчасть, сток) — запрещены. Большинство слайдов — БЕЗ изображений.

**Где изображения уместны:**
1. **Обложка → ГЕРОЙ-КАДР сферы деятельности** (рекомендуется): красивое,
   магазинного качества фото из ОТРАСЛИ/деятельности компании (для перевозчика/
   автозапчастей — фура на трассе; для отеля — здание; для агро — поля/ферма; для
   IT — абстракция/офис). Full-bleed + полупрозрачная плашка под текст. Цвета —
   в палитру дека. НЕ продуктовое фото-крупный-план запчасти, НЕ дешёвый сток-кадр.
   Логотип компании — опционально поверх, если найден чистый.
2. **Активо-ёмкий бизнес** (недвижимость/отель/завод/агро) → можно ОДНО фото
   конкретного актива (как фото здания в меморандуме недвижимости).
3. Тело слайдов — БЕЗ фото (только чарты/framework'и). Исключение — п.2.

**Как получить и проверить (алгоритм, на входе только ИНН+сайт):**
1. Бренд/отрасль из реестра: `get_company_info(inn).name_short` + `okved_name`.
2. **Герой-кадр обложки:** `image_search.search_images("<тема отрасли> <красиво>")`
   (напр. «фура трасса закат», «гостиница фасад», «поля агро»), `download_images`,
   фильтр ≥1200px ширина.
3. **ВИЗУАЛЬНАЯ ПРОВЕРКА ЗРЕНИЕМ (обязательно):** открой 5–10 кандидатов через Read,
   выбери ОДИН: магазинного качества, релевантный отрасли, цвета гармонируют с
   палитрой дека (для navy-дека — тёмные/закатные тона), без водяных знаков и
   сток-пошлости. Не прошёл — обложка = чистая типографика (это тоже хорошо).
4. **Логотип (опц.):** `search_images("<бренд> логотип")` → проверка зрением: годится
   только чистый логотип (не баннер/коллаж марок/скриншот/thumbnail). Нет — пропустить.
5. **Фото актива** (только активо-ёмкие): «<бренд> завод/здание» → проверка зрением.

**Запрещено:** ставить картинку без проверки зрением; продуктовые/стоковые фото в
теле; любые изображения «для красоты».

## 11. ЧЕК-ЛИСТ НАПОЛНЕНИЯ (перед передачей в рендер)

- [ ] Все action-titles — выводы, не ярлыки; арифметика сходится с графиками.
- [ ] Нет противоречий «растёт» vs падающая последняя точка (год-исключение помечен).
- [ ] Линия маржи подписана; football-field — подписи снаружи полос, есть база.
- [ ] В KPI-карточке бизнес-метрики, не «100% долей».
- [ ] Катализаторы ДО оценки.
- [ ] Дисклеймер нейтрален (без намёка на серое, без обещания цены, без императива).
- [ ] Есть rationale для собственника и идентификация отправителя (не плейсхолдер).
- [ ] Логотип проверен зрением ИЛИ его нет; в теле — ноль декоративных фото.
- [ ] У каждого слайда с данными — источник в футере.
